Subject: Proposal: centralise Private Link DNS (DNS Private Resolver + AMPLS) – plan and approvals needed

Hi [Manager],

I'd like your approval to move our Private Link DNS off the enterprise DNS servers and onto Azure DNS Private Resolver, with a single Azure Monitor Private Link Scope (AMPLS) for monitoring traffic.

The problem today
The privatelink.* zones for Storage, Key Vault, SQL and Azure Monitor are hosted on the domain controllers and updated by hand. Every new private endpoint needs a DNS ticket. Records go stale when an endpoint's IP changes, and on-prem and Azure can resolve the same name differently. Those mismatches are behind several hard-to-diagnose connectivity issues.

What changes
- The DNS servers keep only conditional forwarders to a DNS Private Resolver in the hub.
- All privatelink zones live centrally in the connectivity subscription.
- Private endpoints register their own DNS records through Azure Policy, so DNS tickets for them go away.
- One shared AMPLS in the management subscription carries Azure Monitor traffic privately.

How we'll do it
We build first with no client impact. Then we move the zones in four weekly waves, lowest risk first: Key Vault, then databases and messaging, then apps and storage, and finally blob storage with AMPLS. Each wave is one change and has to pass a scripted parity check first: the old and new DNS paths must give identical answers. The cutover script rolls back automatically if validation fails. The scripts and Terraform are written, and the full plan is on the wiki: [wiki link].

Proposed timeline
Build from 9 Nov, waves from late November, done mid-December. Wave 4 and the lock-down land close to the Christmas change freeze, so we may need to move those into January.

What I need from you
1. Approval of the approach and wave plan.
2. Four CAB windows, one a week.
3. DNS / Network Ops time for each cutover window (about 1–2 hours each).
4. Sign-off to assign two policies at the landing-zones management group (auto-register private endpoints; flag private DNS zones created in workload subscriptions, audit only to start).
5. Support with the app-team comms about the spoke DNS change and the new rules.
